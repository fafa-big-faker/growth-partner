# 手机音效延迟修复

用户反馈 App 手机外放中所有音效接近一秒延迟，PC 正常。现有短音效每次创建 HTML Audio，首屏只缓存文件，没有保存解码结果。按钮音效又在点击冒泡阶段才触发。

执行方案：
1. 首屏资源下载完成后，用同一个 interactive AudioContext 解码并缓存 12 个短音效，包括锻造循环。BGM 继续串流，保留音量、文件与演出时间。
2. 用户触摸/键盘输入时解锁音频。点击音效在捕获阶段触发，先于同步界面渲染。
3. 已解码音效直接启动独立 BufferSource，保留分组限流、取消、静音和后台保护；不支持解码时保留原播放器回退。解码超时不阻塞登录。
4. 回归测试低延迟路径、取消竞态、循环、回退、登录等待与真实浏览器解码；完成项目检查后直接发布，确认线上版本。模拟测试不能代替手机扬声器实际延迟验收。

验证完成：564 项 Node 回归通过，全部 Python 素材测试、JS/Python 语法及资源清单检查通过。`tests/audio-web.browser-check.cjs`使用真实 Chrome 解码全部 12 个音效，并分别执行鼠标/触摸输入；播放时不再请求短音效文件，不再使用 HTML Audio，程序端调度约 0–0.1ms。此数字不包含系统混音与扬声器输出，不作为手机实测延迟。BGM、音量、演出、资源文件保持原样。
