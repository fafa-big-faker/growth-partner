# 入境画卷转场

用户已确认设计并授权实现、检查及发布，无需重复确认。

- 入境准备完成才开始约720ms转场：100%短暂停留，文案先退、首屏背景叠化到登录背景，登录表单轻移6px显现。Logo沿用现有书写动画，在叠化中段开始；不额外串行等待完整Logo动画。
- 账号、数据、当前树和角色资源准备好后，登录页约700ms淡出并轻微放大至1.02；游戏场景同时显现，背包与底栏晚80ms从6px归位。复用全部现有图片，不新增美术、声音、Canvas或重型模糊滤镜。
- 全程只有一个入场操作。准备失败仍留登录页；转场中的两页均不可交互，完成后解除临时样式和锁。取消、动画API失败、切后台均有结束路径，不依赖单一animationend事件。
- 新手引导必须在游戏转场完全结束后启动并重新检查当前账号、页面和砍树次数。不得仅隐藏已经拦截输入的引导层。
- 减少动态效果时使用短淡入淡出，去掉位移和缩放；无动画API直接完成。两种账号均适配，不改变页面日常导航效果、游戏数据或APK壳。
- 按用户偏好不做截图视觉验收；用本地模拟账号进行实际浏览器的事件、可交互性、时间轴和布局断言，禁止真实数据库写入。

实现边界：独立SceneTransition模块负责动画生命周期；LoginBoot负责资源完成和登录首次展示；Auth负责验证和游戏初始化；Router返回渲染完成结果。后续维护不得把动画时长作为资源加载成功判据。
