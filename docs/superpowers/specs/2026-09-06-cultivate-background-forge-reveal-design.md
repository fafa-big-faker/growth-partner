# 修仙背景与锻造揭晓设计

## 目标

恢复修仙页的完整场景背景，消除 PC 端砍树舞台的图片重复拼接，并在不增加新美术资源的前提下，为锻造加入约 3 秒的渐进式奖励揭晓动画。

## 背景

`#player-dashboard[data-player-scene="cultivate"]` 当前把 `--player-scene` 设置为 `none`，导致修仙页外层只显示代码渐变。砍树舞台使用的 `700 x 519` 背景没有声明 `background-repeat`、`background-size` 和 `background-position`，因此在 PC 宽度超过图片宽度时按浏览器默认行为重复平铺。

## 背景设计

- 修仙页外层恢复 `assets/runtime/v2/backgrounds/cultivate.webp`。
- 外层背景使用 `center top / cover no-repeat`，保留纯色作为资源失败时的兜底。
- 砍树舞台使用同一资源的独立居中裁切，声明 `center 42% / cover no-repeat`。
- 舞台保留极淡的青绿色遮罩，仅用于维持人物、树和文字的对比度，不增加模糊层。
- 当前资源先通过 CSS 正确适配；未来单独制作砍树背景时，推荐画布约为 `1600 x 700`。

## 锻造揭晓设计

锻造弹窗的概率说明保持不变。点击锻造后，弹窗内容原位切换到揭晓舞台，避免叠加第二个弹窗。

动画状态：

1. `rolling`：候选斧头图标与名称同步轮换，间隔从 `320ms` 逐渐缩短到约 `76ms`，图标轻微左右摇晃。
2. `waiting`：进度停在 `94%` 并显示“灵力凝聚中”，等待真实 `Game.forge()` 返回。
3. `revealed`：短促闪光后显示真实结果，进度变为 `100%`，最终图标放大后稳定落下。
4. `failed`：真实锻造返回空结果时停止动画，不显示成功文案，由现有业务错误提示说明原因。

动画只展示 `FORGE_POOL` 中配置的武器。真实抽取、扣除材料和发放道具仍完全由现有 `Game.forge()` 决定，轮换内容不影响概率和结果。

## 时序与并发

- 点击后立即由现有 `OperationGuard` 锁定 `forge` 操作。
- 动画和 `Game.forge()` 同时启动。
- 最短展示时长约 `2.8s`；数据提前返回时等待动画完成，数据较慢时停在 `94%`。
- 只有真实结果存在时才播放最终揭晓并显示装备按钮。
- 动画运行期间禁止关闭弹窗和再次点击锻造。

## 视觉规则

- 使用现有正式斧头图标，不使用 emoji 或临时占位图。
- 武器名称始终采用其品质色；状态文案使用低强调墨绿色。
- 闪光只出现一次，持续不超过 `360ms`，避免持续高亮和廉价霓虹感。
- 进度条使用现有青绿与暖金行动色，结构保持简洁。
- 对 `prefers-reduced-motion` 用户缩短轮换并取消连续摇晃。

## 验证

- 静态测试确认修仙页不再设置空背景，舞台明确使用 `cover` 与 `no-repeat`。
- 单元测试确认轮换间隔递减、进度在真实结果前不达到 `100%`、最终展示业务返回的结果。
- 回归测试确认锻造仍使用稳定操作键，失败不会打开成功状态，现有 `55` 项测试不回退。
