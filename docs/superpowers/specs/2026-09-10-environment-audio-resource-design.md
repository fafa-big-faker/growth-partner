# 正式/测试隔离与 Android 体验优化设计

## 目标

1. 测试天道只管理测试修炼者的任务，正式天道只管理正式修炼者的任务。
2. Android App 的短音效改走原生低延迟通道，网页和手机浏览器保留现有 Web Audio 路径。
3. Android App 内置当前已发布资源作为基础包，首次启动不再从 GitHub Pages 下载整包；网页端减少登录前无必要的动作资源下载。

## 任务环境隔离

`xiu_tasks` 新增 `audience_role TEXT NOT NULL`，只允许 `player` 与 `player_live`。所有任务读取、创建、编辑、发布、撤回和删除都必须按 `DB.playerRole` 过滤。当前线上 4 条任务是 2026-09-10 创建的正式任务：迁移时原记录归 `player_live`，同时复制一份到 `player` 作为测试服初始快照。复制后 UUID 独立，之后两边互不影响。现有 10 条历史提交均属于测试账号且引用已删除任务，不改动、不删除。

迁移必须幂等：重复执行不会重复复制任务；使用迁移标记列 `environment_seed_key` 对复制关系建立唯一索引。网页在字段尚未迁移时不再静默回退到共享任务，直接显示读取/保存失败，防止重新造成串服。

## Android 原生音效

网页浏览器继续使用已解码的 interactive AudioContext。Android 1.0.3 新增一个能力极小的 JavaScript 接口，只接受白名单音效名、0~1 音量、0.5~2 倍速、是否循环及停止指令，不暴露文件、账号或网络能力。原生使用 `SoundPool` 与 `USAGE_GAME` 播放 12 个短音效，BGM 仍由网页单实例播放。网页音频管理器优先调用原生桥，桥不存在或尚未准备好时回退 Web Audio，继续保留分组并发、静音、切后台、弹窗取消和循环停止语义。

当前网页更新无法改变旧 APK 的 WebView 音频管线，因此该修复交付为同签名覆盖安装的 1.0.3（versionCode 4）。网页仍兼容 1.0.2 和普通浏览器。

## Android 内置基础资源包

当前高密度手机准备包为 216 个文件、7.87MiB，其中 90 个角色动作帧占 2.21MiB，13 个音频占 2.33MiB。主要瓶颈是国内网络访问 GitHub Pages 时大量小请求的往返与缓存写入，不是总字节数。

构建 1.0.3 时，把当前 `BootAssetManifest` 描述的文件和精确 URL/字节/SHA256 映射内置 APK。Android 仅对可信站点下、且 URL、长度、指纹均与内置清单吻合的 `assets/runtime/` 请求返回本地内容；新版网页出现不同版本或指纹时自动走网络。网页资源准备器识别原生包中已具备的条目，只下载缺失或已变化的文件。因此安装包预计增至约 8~10MiB，首次启动不再下载当前 7.87MiB，后续网页和配置仍可热更新。

为避免普通手机浏览器登录前下载九把仙斧的全部 90 帧，首屏清单拆成公共资源和延后资源。登录前准备登录、美术框、道具图标、音频等公共资源；账号验证后只准备当前仙树、当前装备仙斧的 10 帧及当前页面背景。其余仙斧动作在武器首次出现或换装前准备，并保留现有加载反馈，不能显示空图。

## 安全与兼容

- 不修改玩家存档、背包、邮件、提现或历史提交。
- 原生接口不接收 URL，不读取页面数据，不执行任意命令。
- 只拦截 `NavigationPolicy` 允许的正式站点资源，TLS 错误仍拒绝。
- APK 包名、签名、最低 Android 版本保持不变，可覆盖安装 1.0.2。
- 浏览器、旧 APK、原生资源缺失、SoundPool 加载失败均有原网络/Web Audio 回退。

## 验证

- SQL 结构与幂等迁移测试；测试/正式任务读写隔离测试。
- Web Audio 与原生桥单元测试，覆盖重叠、取消、循环、静音、后台和回退。
- JVM 测试覆盖原生资源 URL 白名单与精确清单匹配。
- 真实 Chrome 冷/热缓存检查，确认普通浏览器不再登录前请求全部 90 帧。
- 构建、签名、包名、权限、版本、APK 内置资源数量和指纹检查。
- 发布后核对 GitHub Pages 提交；无连接设备时明确要求用户在真机覆盖安装后验收音效与首次启动速度。
