# 游戏音频接入设计

## 目标

用一首循环背景音乐和六个通用音效覆盖游戏的关键反馈，不增加复杂设置，不让音频加载或浏览器播放限制影响登录及操作。

## 资源映射

- `bgm-main.mp3`：玩家登录成功后循环播放。
- `ui-tap.wav`：主要按钮、页签和底部导航点击。
- `ui-open.wav`：页面切换及弹窗打开。
- `chop-hit.wav`：每次砍树命中。
- `item-drop.wav`：掉落物出现。
- `forge-process.wav`：锻造动画过程。
- `forge-success.wav`：锻造结果揭晓。

## 交互规则

- 登录按钮属于浏览器允许播放的用户手势，验证成功后启动背景音乐。
- 底部导航右上方提供一个悬浮图标静音按钮，不增加独立设置页；静音状态写入 `localStorage`。
- 音效允许并发，重复播放时使用独立播放实例；背景音乐保持单实例循环。
- 页面切换播放一次打开声，弹窗打开播放一次打开声；由全局点击监听补齐按钮点击声，带禁用状态的控件不播放。
- 十连砍每次动作命中播放砍树声，每次掉落出现播放掉落声。
- 锻造开始播放过程声，成功揭晓时停止过程声并播放成功声；失败或关闭也必须停止过程声。
- 管理端保留界面音效，但不自动播放背景音乐。

## 容错与性能

- 所有 `play()` 异常都被吸收并记录，不得打断游戏 Promise 链。
- 音频加入登录预加载清单，但预加载失败不得阻塞登录。
- 资源总量约 1.75 MB，现有编码可直接上线，无需再次压缩。

## 验证

- 单元测试验证资源映射、静音持久化、并发音效、背景音乐启停和失败容错。
- 静态测试验证登录、路由、弹窗、砍树、掉落、锻造触发点已接入。
- 发布前执行完整 Node 测试、JavaScript 语法检查和 `git diff --check`。
