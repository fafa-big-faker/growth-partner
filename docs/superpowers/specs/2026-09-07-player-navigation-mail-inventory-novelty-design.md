# 玩家切页、邮件与背包新标记设计

## 目标

减少邮件和底部导航的可感知等待，杜绝重复删除确认弹窗，并为新获得或数量增加的背包物品提供持久的“新”标记。

## 已确认约束

- 不新增第三方前端依赖。
- 不为“新”标记增加 Supabase 表或字段。
- “新”状态按当前浏览器和当前玩家账号分别保存在 `localStorage` 中；刷新、关闭页面和重新登录后保留，换设备不同步。
- 普通道具按道具 ID 标记；每把武器按独立武器实例 ID 标记。
- 点击对应道具或武器的详情后清除其“新”状态；以后再次获得或数量增加时可以重新出现。
- 批量删除已读邮件时，任何仍有未领取附件的邮件都必须保留。
- 不执行浏览器视觉验收，除非用户另行要求。

## 根因

### 邮件

`showMailModal()` 在创建弹窗前等待 `DB.getMails()`，所以网络慢时点击看起来无响应。邮件列表加载完成后又调用 `_updateMailBadge()`，产生第二次邮件查询。单封删除在确认弹窗出现前没有唯一状态，连续点击会创建多个相同确认弹窗。

### 底部导航

任务页在写入页面内容前并行等待三次任务查询和一次提交记录查询；天道酬勤页在写入页面内容前等待提现记录。路由没有渲染序号，快速切换时较早请求的迟到结果仍可能覆盖当前页面。重复点击已激活页签也会重新渲染整个页面。

### 背包新标记

当前没有独立的新物品状态。普通奖励大多经过 `Game.grantItem()`，但每日签到、合成、十连砍批量落库和锻造武器存在各自的更新路径，因此只在一个领取按钮上添加标记会漏场景。

## 方案选择

### 采用：短时缓存、请求合并和即时页面骨架

这是改动范围与真实收益最平衡的方案。缓存用于即时展示最近一次成功数据，后台请求完成后再刷新当前页面；相同的在途请求共用一个 Promise。路由渲染序号阻止迟到结果覆盖新页面。

### 未采用：所有页签永久挂载 DOM

切换速度最快，但会长期保留动画、弹窗引用和页面内临时状态，容易产生隐蔽的数据同步问题，且对当前单文件页面结构改动过大。

### 未采用：只增加加载动画

只能掩饰等待，不能减少查询次数、重复请求或异步竞态，因此不足以解决本次问题。

## 详细设计

### 1. 玩家数据缓存

新增一个小型纯 JavaScript 缓存模块，为邮件、任务组合数据和提现记录提供：

- 最近一次成功结果与更新时间。
- 可配置的短时有效期。
- 同一资源的在途请求合并。
- 明确的 `invalidate()`，在领取、提交、审核结果变化、删除、提现等写操作后失效。

邮件缓存由邮件弹窗、邮件页面和顶部未读角标共用，避免同一时刻重复读取。邮件和任务默认允许短时间显示旧数据，但任何写操作成功后都强制刷新对应资源。

### 2. 路由与页面渲染

`Router.playerTab(tab)` 在点击时立即完成页签高亮和场景背景切换，并为每次导航生成递增的渲染序号。异步页面只能在序号仍是最新且当前页签未改变时写入 DOM。

- 已激活页签再次点击时不重复整页渲染。
- 有缓存时立即渲染缓存内容，后台静默更新。
- 无缓存时立即渲染稳定尺寸的轻量骨架，避免旧页面停留造成“没点到”的感觉。
- 任务数据改为一次读取全部已发布任务，再按类型在浏览器内拆分；与玩家提交记录并行，因此由四个请求减少为两个。
- 天道酬勤主体先用本地 `Game.state` 立即绘制，提现记录独立异步填充。
- 页面只使用约 120ms 的轻微淡入，不用会拖慢操作感的长位移动画，并尊重 `prefers-reduced-motion`。

### 3. 邮件交互

打开邮件时立即创建弹窗或页面容器，再从共享缓存渲染；首次无缓存时显示骨架。读取邮件只更新当前邮件和共享缓存，不再额外重新查询未读角标。

邮件列表工具栏显示“删除已读”和可删除数量。可删除集合必须同时满足：

- `isRead === true`。
- 不存在未领取附件，即没有附件，或者附件已经领取。

批量删除使用一次带玩家账号条件和 ID 集合的 Supabase 更新。成功后一次性从本地缓存移除并刷新角标。没有符合条件的邮件时按钮禁用。

`UI.confirm()` 增加可选唯一键。具有相同键的确认框已存在时直接复用，不再创建第二个。单封删除和批量删除分别使用稳定键，确认后的数据库操作继续通过 `UI.runLockedAction()` 防止重复提交。

### 4. 背包新标记

新增独立的 `InventoryNovelty` 模块，保存以下角色隔离状态：

- `newItemIds`: 尚未查看的普通道具 ID 集合。
- `newWeaponIds`: 尚未查看的武器实例 ID 集合。
- 最近一次物品数量和武器实例快照，用于重新登录时识别数据库侧新增。

首次使用某个玩家账号时只建立基线，不把已有全部物品标为新。之后每次同步时：普通道具数量高于上次快照则标新，新出现的武器实例则标新。已知的本地发放成功后立即同步状态，使角标不必等待下一次页面刷新。

需要覆盖的非统一更新路径包括：每日签到、合成目标物、十连砍批量奖励和锻造武器。消费或出售成功后也更新快照，保证未来数量从较低值再次增加时能够重新标新。

背包格子右上角显示小型“新”角标，不遮挡右下角数量。调用 `showItemDetail(itemId, instanceId)` 时先清除对应状态并局部重绘当前背包，再打开详情。武器被直接装备或出售时也清除其状态。

## 错误与一致性

- 缓存只在请求成功后替换，网络失败时保留上次成功内容并给出轻量错误提示。
- 过期异步结果可以写入缓存，但不能写入已经离开的页面 DOM。
- 批量删除失败时不修改本地邮件集合。
- 新标记只在数据库写入或 RPC 成功后记录；失败与回滚不会产生假“新”。
- `localStorage` 不可用时退化为当前会话内存状态，不阻断游戏功能。

## 测试

- 缓存：有效期、请求合并、失效和失败时保留旧值。
- 路由：重复页签不重渲染、迟到请求不能覆盖当前页、任务只发起两次读取。
- 邮件：弹窗立即出现、角标复用缓存、批量删除过滤未领取附件、单次数据库更新、相同确认键不叠加。
- 新标记：首次基线不标新、数量增加标新、数量降低后再次增加重新标新、武器实例独立、账号隔离、点击详情清除。
