# 十连砍解锁、BUFF 着色与锻造动画优化设计

## 目标

为十连砍增加中卡拉米仙阶门槛，修正倍率类 BUFF 的目标品质颜色，并精简、连贯化锻造抽取界面。

## 已确认规则

- 不改变十连砍开关当前的展示位置和样式。
- 中卡拉米对应仙阶 ID `2`；玩家仙阶达到 `2` 或更高时可以使用十连砍。
- 未解锁玩家尝试开启十连砍时，开关恢复关闭并提示“突破至中卡拉米后解锁”。
- BUFF 类型 1～5属于奖励倍率类：`value1` 表示目标奖励品质，使用该品质颜色；其他动态数值继续使用 BUFF 自身品质颜色。
- 锻造弹窗移除标题上方 Logo，保留标题和副文案。
- 锻造结果仍以数据库返回为准，不能为了动画流畅提前伪造结果。
- 不进行浏览器视觉验收，除非用户另行要求。

## 十连砍解锁

新增单一解锁常量或判定函数，以 `realmLevel >= 2` 为准。玩家打开十连砍开关时先检查仙阶，再检查砍树次数；未达到仙阶时关闭开关并提示解锁条件。

`PlayerView.doChopTen()` 和游戏逻辑入口增加相同的兜底校验，防止旧的本地开关状态、控制台调用或管理员降阶后绕过限制。兜底失败时不消耗次数、不写数据库，也不开始角色动画。

## BUFF 数值颜色

`WeaponAffixes.formatSkill()` 为每个动态值独立决定颜色等级：

- `effectType === 'reward_multiplier'` 且键为 `value1` 时，颜色等级取该值本身，即奖励品质 ID。
- `value2`、`value3` 以及返还砍树次数类型的全部动态值，颜色等级继续取 `buffQuality`。

文本内容和概率、倍率计算不变，仅改变生成的 CSS 品质类。

## 锻造界面与动画

标题区删除 `forge-modal-icon`，并收紧标题区与抽取舞台之间的垂直间距，避免顶部信息拥挤。

现有动画停顿是因为候选序列只播放约 1.17 秒，随后固定到 94% 并等待数据库。新时间轴分为三段：

1. 加速段：保留当前逐渐加快的候选切换，进度条线性前进到约 90%。
2. 等待段：若数据库仍未返回，以最高速度持续循环候选图片和名字；进度条继续平滑趋近 98%，不提前到达 100%。
3. 揭晓段：真实结果返回后停止循环，将进度条从当前视觉位置平滑补到 100%，同时显示真实斧头、名称与结果详情。

对 `prefers-reduced-motion` 用户保留精简动画，不强制持续高速抖动。数据库失败时结束等待循环并恢复初始状态。

## 测试

- 仙阶 1 尝试开启或执行十连砍时被阻止，仙阶 2 及以上保持原逻辑。
- 仙阶拦截发生在动画和数据库调用之前。
- 奖励倍率 BUFF 的 `value1` 使用目标品质颜色，其他值仍使用 BUFF 品质颜色。
- 锻造弹窗不再渲 Logo。
- 模拟慢速结果 Promise 时，加速序列结束后候选仍持续变化；结果到达后停止并平滑完成进度。
- 模拟快速成功、失败和 reduced-motion 路径。
- 完整 Node、JavaScript、Python 和资源检查通过后发布。
