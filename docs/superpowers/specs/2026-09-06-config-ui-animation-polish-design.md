# 配置、界面与角色动画精修设计

## 目标

修正签到、商店、背包和十连砍的交互问题，用带武器的新版待机与砍树图集统一角色表现，并把配置同步、美术切割和发布检查沉淀为可重复流程。

## 配置与数据

- 奖池表第一行英文参数统一为 `pack_id`、`item_ids`、`item_quantities`、`quality_id`、`quality_note`。
- 每日签到奖励表第一行英文参数统一为 `item_ids`、`item_quantities`。
- 商店表新增商品文案参数 `description`，`note` 继续只作为配置备注。
- 同步脚本按第一行英文参数名建立列映射，并对必需字段进行校验，避免飞书列顺序变化后静默读错。
- 每日签到卡片和领取结果都读取 `dailySignInRewards`，不再显示任务表中写死的砍树次数图标。

## 签到与商店界面

- 累签节点只保留一个奖励图标；奖励数量放在图标右下角，领取状态放在左上角，以位置而不是重复图像表达状态。
- 进度线与节点保持轻量、清晰；可领取节点使用暖金描边，已领取节点降低饱和度，未解锁节点降低透明度。
- 商店卡片在名称下显示最多两行商品文案，价格作为卡片底部的独立兑换按钮。锁定与售罄状态沿用同一按钮区域，避免整张卡片承担按钮语义。
- 武器出售后的局部重绘保留当前背包页签，普通道具和武器之间不再意外跳转。

## 角色动作与十连砍

- 砍树 V2 图集使用 `#FF00FF` 竖线检测真实边界，去除分隔线后导出每把武器六帧。
- 待机图集每把武器四帧。切割后根据透明像素包围盒统一缩放、保留水平安全区并统一脚底基线，避免裙摆被裁断和人物跳动。
- 当前装备同时决定待机帧集与砍树帧集；切换装备后立即刷新两套资源，未知武器回退到默认斧头。
- 十连砍先完成一次原子结算，再按独立时间轴播放十次表现。速度从 1 倍线性提升至 3 倍，动作时长、两次挥砍间隔、树震动和掉落物时长共同随倍率缩短，中间不穿插待机动作。

## 登录交互

- 开始游戏按钮增加悬浮、按下和键盘聚焦状态。
- 点击后立即进入不可重复提交的加载状态；真实资源预加载与数据初始化完成后才进入游戏，失败则恢复按钮并显示错误。

## 长期规范

- 在仓库根目录维护 `AGENTS.md`，记录中文沟通、十分钟无进展汇报、默认不做视觉验收、页签状态保持、凭据安全等硬约束。
- 在 `docs/PROJECT_PLAYBOOK.md` 记录需求、配置、测试和发布流程。
- 在 `docs/ASSET_PIPELINE.md` 记录图集命名、分隔线、切割尺寸、透明边界和联系表生成方式。
- 保留自动化测试、图集验证和 `git diff --check` 作为发布前检查；禁止提交 `apikey`、令牌或带凭据的远程地址。

## 验证

- 自动测试覆盖动态签到奖励、商店文案、累签单图标、背包页签保持、四帧待机切换、V2 六帧砍树和十连砍完整节奏曲线。
- 图像脚本验证九套待机共 36 帧、九套砍树共 54 帧，输出尺寸、透明通道和非空内容均正确。
- 运行全部 Node 测试、JavaScript 语法检查、Python 编译检查和 Git 空白错误检查。
- 本轮按用户要求不做浏览器视觉验收；自动检查通过后直接发布。
